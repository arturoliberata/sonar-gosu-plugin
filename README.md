# Gosu plugin for SonarQube

[![CI](https://github.com/arturoliberata/sonar-gosu-plugin/actions/workflows/ci.yml/badge.svg)](https://github.com/arturoliberata/sonar-gosu-plugin/actions/workflows/ci.yml)
[![License](https://img.shields.io/badge/license-Apache%202.0-blue.svg)](LICENSE)

Adds the **Gosu** language (the JVM language used by Guidewire applications) to SonarQube:
syntax highlighting, metrics, duplication detection, a symbol table and code-quality rules.

> Community project. It is not affiliated with or endorsed by Guidewire Software or SonarSource.

## Features

| Data | Details |
|---|---|
| Issues | 7 rules, all active in the built-in **Sonar way** profile |
| Measures | lines of code, comment lines, functions, classes, statements, cyclomatic complexity |
| Executable lines | one per statement; lines a coverage report is expected to cover |
| Duplications | copy-paste detection; `uses` and `package` lines are excluded |
| Syntax highlighting | keywords, strings, numbers, annotations, comments, doc comments |
| Symbol table | fields, parameters, locals, loop and catch variables linked to their uses |

**File types:** `.gs` (classes), `.gsx` (enhancements) and `.gsp` (programs) are fully analyzed.
`.gst` templates get highlighting, line metrics, duplication and the line-based rules only, because
the grammar does not cover template syntax. The list is configurable with `sonar.gosu.file.suffixes`.

### Rules

| Key | Type | Checks |
|---|---|---|
| `ParsingError` | Code smell | the file could not be parsed (tree-based rules are skipped for it) |
| `EmptyCatchBlock` | Bug | `catch` with an empty body (a comment inside is accepted) |
| `PrintStatement` | Code smell | `print(...)`, `System.out`, `System.err` |
| `TooManyParameters` | Code smell | more than 7 parameters on a `function` / `construct` (configurable) |
| `DuplicateUses` | Code smell | the same `uses` statement twice |
| `LineLength` | Code smell | lines over 120 characters (configurable) |
| `TodoComment` | Code smell | `TODO` / `FIXME` in comments |

## Installation

1. Download `sonar-gosu-plugin-<version>.jar` from the
   [Releases](https://github.com/arturoliberata/sonar-gosu-plugin/releases) page.
2. Copy it to `<SONARQUBE_HOME>/extensions/plugins/` and restart SonarQube.
3. Check **Rules → Language: Gosu** and **Quality Profiles → Gosu**.

**Compatibility:** built against the SonarQube plugin API 9.14, so it targets SonarQube 9.9 LTS and newer.
Tested with SonarQube Community Build 26.9.

Then scan a project the usual way. For example, with `sonar-project.properties`:

```properties
sonar.projectKey=my-gosu-project
sonar.sources=.
sonar.inclusions=**/*.gs,**/*.gsx,**/*.gsp,**/*.gst
```

The [`sample-project`](sample-project) folder triggers every rule and is ready to scan.
[docs/local-testing.md](docs/local-testing.md) walks through a complete local setup.

## Coverage

Coverage is imported by SonarQube itself, not by this plugin:

- **Generic test data** works for any language: produce the
  [generic coverage XML](https://docs.sonarsource.com/sonarqube-server/latest/analyzing-source-code/test-coverage/generic-test-data/)
  and set `sonar.coverageReportPaths`.
- **JaCoCo:** Gosu compiles to JVM bytecode, so a JaCoCo XML report can be passed with
  `sonar.coverage.jacoco.xmlReportPaths`. Whether SonarQube's JaCoCo importer maps Gosu classes
  to `.gs` files has **not been tested** yet. Reports are welcome.

## How it works

The plugin follows SonarQube's
[supporting new languages](https://docs.sonarsource.com/sonarqube-community-build/extension-guide/developing-a-plugin/supporting-new-languages) guide:

| Guide step | Where |
|---|---|
| 1. Grammar | [`Gosu.g4`](src/main/antlr4/org/sonargosu/plugin/parser/Gosu.g4): ANTLR 4 port of the official [Gosu.g / GosuProg.g](https://github.com/gosu-lang/gosu-lang/tree/master/gosu-core/src/main/java/gw/internal/gosu/parser/ebnf) (originals in [`grammar/original/`](grammar/original)) |
| 2. Parser | Generated by ANTLR at build time; [`GosuParserFacade`](src/main/java/org/sonargosu/plugin/parser/GosuParserFacade.java) runs it |
| 3. Grammar tested on real code | [`GosuCorpusTest`](src/test/java/org/sonargosu/plugin/parser/GosuCorpusTest.java) parses the whole gosu-lang source tree in CI: **99.9%** of its valid files parse |
| 4. Parse tree visitors | [`visitors/`](src/main/java/org/sonargosu/plugin/visitors) for metrics and the symbol table; [`checks/`](src/main/java/org/sonargosu/plugin/checks) for rules |
| 5. Scanner sensor | [`GosuSensor`](src/main/java/org/sonargosu/plugin/GosuSensor.java) |

### Grammar notes

`Gosu.g4` lists how it differs from the 2013 originals at the top of the file. In summary:

- **Converted from ANTLR 3:** backtracking and syntactic predicates were removed.
  The "adjacent tokens" checks on `<=`, `>>` and similar operators were dropped, so the grammar
  accepts slightly more than the compiler does.
- **Added for newer Gosu, found by parsing the gosu-lang sources:** annotation types, `reified`,
  `uses X#member`, interface methods with bodies, `property Name : Type`, rational literals (`1.5r`),
  unit expressions (`5 kg`), use-site annotation targets (`@get:Anno`), nested string templates,
  `\` line continuation in strings, and programs that `extends` a class.

### Known limitations

- Symbol resolution is lexical: it doesn't use type information, and members reached through
  `this.x` or `obj.x` are not linked.
- Highlighting, duplication and line metrics use a separate hand-written tokenizer
  ([`lexer/GosuLexer`](src/main/java/org/sonargosu/plugin/lexer/GosuLexer.java)), so they still work
  on files that fail to parse.
- Uses `org.sonar.api.utils.log.Loggers`, which is deprecated in newer plugin APIs.

## Building from source

Requires JDK 17+. Maven is downloaded by the wrapper.

```bash
./mvnw package        # macOS / Linux
mvnw.cmd package      # Windows
```

The plugin is written to `target/sonar-gosu-plugin-<version>.jar`.
